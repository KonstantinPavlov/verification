# Система периодического аудита прикладной репликации

## 📌 Общее описание
Система предназначена для отложенного (по расписанию) аудита целостности прикладной репликации данных. Изменения из исходной PostgreSQL непрерывно стримятся в Kafka-топик с политикой сжатия логов (Log Compaction), аккумулируя только последние состояния измененных строк по их Primary Key (PK). Раз в сутки (или по расписанию) запускается сервис-верификатор, который вычитывает сжатый лог, сравнивает строки между источником и приемником, а все обнаруженные расхождения фиксирует в партиционированную таблицу аудита.

## 🧱 Функциональные требования к компонентам
1. CDC Publisher (Работает непрерывно)
Чтение WAL: Подключается к replication_slot исходной PostgreSQL и слушает события INSERT, UPDATE, DELETE.
Ключ события в Kafka: Отправляет сообщения в топик, где в качестве Kafka Message Key строго используется Primary Key строки (в формате JSON для поддержки составных ПК).
Обработка удалений (Deletes): При удалении строки отправляет в Kafka Tombstone-сообщение (ключ строки + Value = nil или спец-флаг), чтобы зафиксировать факт удаления для последующей проверки в целевой БД.

2. Cron Verifier (Работает по расписанию)
Пакетное чтение: Вычитывает сжатый топик Kafka от сохраненного offset до актуального конца топика. Благодаря Log Compaction, обрабатывается только одна (последняя) версия строки за весь период.
Сверка данных (Batching): Группирует полученные PK в пачки (например, по 500 штук) и делает SELECT ... WHERE id IN (...) в базу-источник и базу-приемник для минимизации сетевых round-trip'ов.
Логирование расхождений: Сравнивает тела строк. Если обнаружена разница по любым полям, отсутствие строки в одной из баз или некорректное удаление — это считается инцидентом рассинхронизации.

## 📊 Хранение инцидентов (Партиционирование)
Все найденные расхождения верификатор записывает в отдельную таблицу в базе данных аудита.
Стратегия партиционирования: Таблица партиционируется по диапазонам дат (Range Partitioning по полю checked_at). 
Шаг партиционирования — 1 день, что позволит легко удалять старые логи аудита через DROP PARTITION.
Структура таблицы расхождений:
checked_at (Timestamp, Ключ партиционирования) — время проведения проверки.
table_name (String) — имя проверяемой таблицы.
primary_key (JSONB) — PK строки, в которой нашли расхождение.
discrepancy_type (Enum) — тип проблемы (SOURCE_MISSING, TARGET_MISSING, DATA_MISMATCH, DELETE_FAILED).
source_data (JSONB) — слепок данных из источника (null, если строка удалена).
target_data (JSONB) — слепок данных из приемника (null, если строки нет).

## ⚙️ Инфраструктурные требования
Kafka: Топик должен быть создан с флагом cleanup.policy=compact.
PostgreSQL: На источнике параметр wal_level должен быть равен logical.

## 🚀 Критерии приемки (Definition of Done)
Корректность сжатия: При многократном изменении одной строки за день, верификатор на выходе обрабатывает её один раз.
Пакетная запись инцидентов: Запись расхождений в партиционированную таблицу выполняется через COPY или пакетный INSERT для оптимизации скорости.
Graceful Shutdown: При получении сигнала SIGINT/SIGTERM верификатор корректно дописывает текущую пачку батча, фиксирует offset в Kafka и завершает работу без дублирования инцидентов.
